# ASOG 스튜디오

어소그가 진행 중인 프로젝트와 진행하려는 프로젝트를 한곳에서 보는 내부 전용 사이트입니다.
고객에게는 이 주소를 절대 알려주지 않습니다. 모든 고객의 답변이 여기서 다 보입니다.

## 주소

- 스튜디오(내부) : https://asog-studio.pages.dev/
- 고객 사이트    : https://asog-client.pages.dev/  (질문지 · 제안서 · 수정요청)

스튜디오는 열면 코드를 묻습니다. 코드는 Supabase `admin_keys` 테이블에 있습니다.
한 번 넣으면 그 브라우저가 기억하고, 헤더의 `잠그기`를 누르면 지워집니다.
예전 방식(`?a=코드`)도 그대로 열리며, 열린 뒤 주소에서 코드를 지웁니다.

코드가 맞는지는 Supabase의 `admin_ok`가 판단합니다. 화면에서 비교하면
코드가 파일 안에 남아 아무 의미가 없습니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 스튜디오 화면 전체 (고객 목록 · 답변 · 수정 요청 · 바로가기) |
| `questions.js` | 질문지 정의 **사본**. 원본은 고객 사이트(asog-client). |
| `supabase.js` | Supabase 라이브러리 사본. 손대지 않습니다. |

### questions.js 를 고칠 때

원본은 `asog-client/questions.js` 한 곳입니다. 거기서 고친 뒤 이 저장소로
복사해 주세요.

```bash
cp ~/Desktop/asog-client/questions.js ~/Desktop/asog-studio/questions.js
```

복사를 잊으면 답변 화면의 질문 이름이 조용히 옛날 것으로 남습니다.
그래도 사본을 두는 이유는, 한때 고객 사이트에서 직접 불러오게 했더니
그쪽이 잠깐 죽었을 때 스튜디오가 통째로 열리지 않았기 때문입니다.
남의 사이트가 살아 있어야 내 화면이 열리는 구조는 쓰지 않습니다.

## 고객에게 나가는 링크

스튜디오는 고객 사이트와 도메인이 다릅니다. 그래서 고객 질문지 링크,
제안서 링크, 수정 요청 스니펫은 이 페이지 주소가 아니라 `index.html` 위쪽의

```js
var CLIENT_SITE = "https://asog-client.pages.dev/";
```

를 기준으로 만들어집니다. 고객 사이트 주소가 바뀌면 이 한 줄만 고치면 됩니다.

## 배포

Cloudflare Pages가 이 저장소의 `main`을 보고 있습니다.
빌드 과정이 없는 정적 사이트라 build command는 비워 두고,
출력 폴더는 저장소 루트(`/`)입니다. push하면 자동으로 반영됩니다.
