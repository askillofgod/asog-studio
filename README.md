# ASOG 스튜디오

어소그가 진행 중인 프로젝트와 진행하려는 프로젝트, 그리고 고객이 보는 화면이
모두 이 저장소 하나에 있습니다.

## 주소

| 주소 | 누가 보는가 |
|---|---|
| `asog-studio.pages.dev/?k=<고객코드>` | 고객 — 프로젝트 시작 질문지 |
| `asog-studio.pages.dev/proposal.html?k=<코드>` | 고객 — 웹 제안서 |
| `asog-studio.pages.dev/pin.js` | 개발 중인 화면에 붙이는 수정 요청 버튼 |
| `asog-studio.pages.dev/studio/` | **대표만** — 고객 목록·답변·수정 요청 |

스튜디오는 열면 코드를 묻습니다. 코드는 Supabase `admin_keys` 테이블에 있습니다.
한 번 넣으면 그 브라우저가 기억하고, 헤더의 `잠그기`를 누르면 지워집니다.
코드가 맞는지는 Supabase의 `admin_ok`가 판단합니다 — 화면에서 비교하면
코드가 파일 안에 남아 아무 의미가 없습니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 고객이 답변을 쓰는 질문지 |
| `proposal.html` | 고객이 보는 웹 제안서 |
| `pin.js` | 개발 중인 화면에 붙이는 수정 요청 위젯 |
| `questions.js` | 질문 내용 — 고칠 일이 있으면 여기만 보면 됩니다 |
| `supabase.js` | 저장·조회용 라이브러리 (직접 고치지 않습니다) |
| `studio/index.html` | 스튜디오 화면 |

`questions.js`와 `supabase.js`는 **한 벌만** 둡니다. 스튜디오는 `../` 로
같은 파일을 가져다 씁니다. 사본을 두면 한쪽을 고치고 다른 쪽을 빠뜨리게 됩니다.

## 프로젝트 정보

고객을 고르면 답변 위에 프로젝트 정보 칸이 있습니다. `고치기`를 눌러 채웁니다.

- **지금** — 진행 단계, 다음 할 일, 언제까지
- **연락** — 회사명, 담당자, 연락처, 이메일, 사업장 주소
- **계약** — 계약일, 만료일(유지보수), 금액
- **사이트** — 기존 사이트, 도메인, 도메인 만료일, 등록처, 호스팅, 오픈일
- **자료와 메모** — 시안 주소, 제안서 링크, 자유 메모, 그 밖의 링크 몇 개든

시안과 제안서는 자리가 정해져 있어서 프로젝트 정보 아래 파란 버튼으로
늘 맨 앞에 나옵니다. 그 뒤로 프로젝트마다 다른 자료들이 붙습니다.

날짜 옆에는 남은 날이 `D-120` 처럼 붙습니다. 30일 안이면 노란색,
지났으면 빨간색입니다. `다음 할 일`은 맨 위에 크게 나오고, 날짜가 지나면
칸 전체가 붉어집니다.

화면에는 **채워진 항목만** 나옵니다. 비어 있는 것까지 다 그리면 "—" 가
화면을 채웁니다. 무엇이 비었는지는 `고치기`에서 봅니다.

### 계정 정보는 넣지 않습니다

호스팅·도메인 관리자 아이디와 비밀번호는 여기에 적지 마세요.
이 데이터베이스는 스튜디오 코드 하나를 알면 전부 열립니다. 고객 계정까지
들어 있으면 코드가 한 번 새는 순간 피해가 어소그 선에서 끝나지 않습니다.
계정은 비밀번호 관리 앱에 두고, 여기에는 "어디에 있는지"(등록처·호스팅)만
적습니다.

이 값들은 **고객에게 보이지 않습니다.** 고객 질문지는 회사명·묶음·답변만
받아 가고(`brief_load`), 금액이나 메모는 애초에 전달되지 않습니다.

고객 카드의 `수정` 날짜는 **고객이 마지막으로 답을 쓴 시각**입니다.
프로젝트 정보를 고쳐도 이 날짜는 움직이지 않습니다.

## 왼쪽 바로가기

고객을 고르면 왼쪽 아래에 그 프로젝트의 시안·제안서·기존 사이트·질문지
링크가 나옵니다. 프로젝트 정보에 넣은 주소를 그대로 씁니다.

예전에는 이 자리에 특정 고객의 주소를 코드에 박아 뒀습니다. 고객마다
자기 링크를 갖게 된 뒤로 그럴 이유가 없어졌습니다. **새 고객이 생겨도
이 파일을 고칠 일이 없습니다.**

## 고객 추가

스튜디오에서 `+ 고객 추가` → 회사명과 묶음 선택 → 링크가 만들어집니다.
파일을 고치거나 다시 배포할 필요가 없습니다.

## 질문 수정

`questions.js` 의 `MODULES` 만 고치고 push 하면 반영됩니다.
묶음(module)은 고객마다 켜고 끌 수 있습니다.

- `common` 공통 — 모든 고객
- `migrate` 기존 데이터 이전 — 기존 사이트가 있을 때
- `visionfilm` 비전필름 전용
- `closing` 마무리 — 항상 맨 뒤에 붙습니다

## 배포

Cloudflare Pages가 이 저장소의 `main`을 봅니다. 빌드 과정이 없는 정적 사이트라
build command는 비우고, 출력 폴더는 저장소 루트(`/`)입니다. push하면 반영됩니다.

## 옛 주소

이 저장소는 예전 `asog-client` 저장소를 흡수한 것입니다.
`asog-client.pages.dev` 로 나간 링크가 아직 고객 손에 있으므로,
그 배포는 당분간 살려 둡니다. 두 사이트는 같은 데이터베이스를 보기 때문에
어느 쪽으로 답을 써도 스튜디오에 그대로 들어옵니다.
